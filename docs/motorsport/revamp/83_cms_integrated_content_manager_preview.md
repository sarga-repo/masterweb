# CMS Integrated Content Manager Preview

## Status

- Phase: `MSR-CMS-LIVE-5`
- Status: Implemented locally on 2026-08-23
- Scope: Supported Motorsport Single Types and collection entries

## Editorial experience

The existing Strapi Content Manager Preview card is now the entry point for
the Motorsport side-by-side workflow. When an editor opens a supported page
and clicks `Open preview`:

1. Strapi keeps the current entry, collection document, and locale.
2. The action opens the Motorsport split workspace with the Content Manager
   editor on the left.
3. The secure custom frontend Preview opens directly on the right in the
   current browser tab.
4. Saving in the editor refreshes the right pane through the existing live-on-
   save heartbeat; Publish remains the public release boundary.

There is no standalone `Motorsport Live Preview` menu entry. The route remains
registered but hidden so the Content Manager Preview card is the single
editorial entry point.

## Implementation contract

- `cms/src/admin/app.tsx` observes Strapi-rendered Preview controls and routes
  approved Motorsport Single Types and collection entries to the split
  workspace.
- The route preserves the selected UID, `plugins[i18n][locale]`, and for
  collection entries the Strapi `documentId`.
- The native Preview anchor is replaced with a button so one click transitions
  the current tab into the custom workspace without a popup or second tab.
- Back to editor returns to the originating Content Manager editor in the same
  tab.
- The embedded left editor hides its nested Strapi navigation/header layers and
  Content Manager collection menu, leaving the form and Save/Publish controls
  available in the side-by-side workspace.
- The split view adds a compact left entry toolbar matching the reference:
  close control, entry title, Published badge, Draft/Published tabs, preview
  link, Save, and Publish. Its actions trigger the underlying Content Manager
  editor buttons.
- The outer Back-to-editor, page selector, and Open Preview controls are
  removed from the split workspace. The Locale selector remains available in
  the top bar for switching the current Preview language.
- The right pane contains the Motorsport frontend directly; it no longer nests
  Strapi's native Preview page inside a second iframe.
- The custom resolver reads the current entry through the authenticated
  Content Manager API. Single Types resolve their document identifier from
  the response; collection entries use the URL-provided `documentId`. Strapi
  then returns the signed frontend `/api/preview` URL. A one-time admin
  access-token refresh mirrors Strapi's native retry behavior when the session
  token is stale.
- The Frontend Preview bar provides 40%–150% zoom controls in 5% steps. The
  reset value fits the selected device to the available pane, so Desktop is
  automatically reduced enough to preserve the real desktop navigation.
- The second right-side toolbar provides Desktop (1440px) and Mobile (390px)
  viewport layouts. The selected layout is rendered inside a scaled viewport,
  rather than inferred from the split pane width.
- The custom Draft/Published tabs resolve the matching frontend draft or
  published URL while the embedded left editor switches its native status tab.
- The custom Save and Publish buttons mirror the embedded Content Manager
  disabled state. They become active only when the corresponding native action
  is available, show a submitting spinner, and display success or failure
  feedback.
- A successful Save or Publish remounts the right Preview iframe so the pane
  visibly refreshes after the operation completes. Save and Publish are not
  sent when there are no changes to commit.
- Save/Publish state changes are observed directly from the embedded Content
  Manager's button attributes and input/change events, so the custom toolbar
  updates immediately when a field becomes dirty or clean. A low-frequency
  fallback check remains for iframe-level state changes that do not emit a
  DOM event.
- The dirty path is optimistic: `beforeinput`, `input`, and `change` events
  enable Save/Publish immediately, then the next animation frame and native
  button mutation reconcile validation, permissions, and no-op edits.
- The split workspace embeds the authenticated Content Manager editor and a
  direct frontend iframe. The signed Preview URL is generated by Strapi and is
  not hard-coded in the custom component.
- Unsupported collection types and non-Motorsport Single Types retain native
  Strapi Preview behavior. Supported collection records include Motorsport
  events, news articles, media galleries, partners, merchandise, programs,
  regulations, riders, standings, ticket CTAs, top navigation items,
  leadership records, and Site records where the preview path contract exists.

## Limitations

- This is a Strapi admin extension that reproduces the requested integrated
  interaction; it is not the paid Strapi Visual Editing/Live Preview product.
- Save and Publish are forwarded to Strapi's embedded native Content Manager
  controls, so their final server response and validation messages remain
  governed by Strapi. The custom toolbar mirrors the native state and adds the
  requested loading/toast/refresh behavior around it.
- Preview updates are saved-draft updates. Unsaved keystroke-level changes
  are not sent to the frontend until a future `postMessage` bridge is added.
- Page switching inside the split workspace is intentionally removed to match
  the reference layout; reopen Preview from the desired Content Manager entry
  to change page context. Locale switching remains available in the top bar.
- The local Preview service can take several seconds to render after a CMS
  admin rebuild; the preview endpoint still returned HTTP 200 during the final
  layout check.
- The signed `/api/preview` URL is visible to the active browser iframe by
  design; access remains constrained by the existing Preview secret and
  frontend preview validation.
